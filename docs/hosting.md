## Gotchas

**Shared Clerk instance across all three environments.** There is deliberately no separate Clerk production instance yet — Clerk requires a custom domain you own to create one (for DNS-based session/email management), and this project doesn't have one. Decided 2026-08-04: stay on the shared `sk_test_`/`pk_test_` keys everywhere until a domain is purchased, then: buy domain → point at Vercel/Fly → create a Clerk production instance against it → rotate secrets on both platforms, all before any real user signs up.

**Vercel and Fly production deploys are not ordered or atomic.** Vercel auto-deploys `main` the moment it's pushed, via its own GitHub integration — independent of `deploy-production.yml`, which only redeploys the Fly backend and only after `rust.yml`'s "Rust CI" job finishes (not gated on the Node.js CI job at all). There's no guarantee about which one lands first after a merge to `main`.

**Neon: always use the unpooled connection string for `DATABASE_URL`.** `neondatabase/create-branch-action`'s `db_url` output (used throughout `deploy-preview.yml`) is the direct/unpooled string, which is required — sqlx's compile-time `query!`/`query_as!` macros PREPARE then DESCRIBE, and PgBouncer transaction-mode pooling (the `-pooler` hostname) can route those two calls to different backend connections, producing a `prepared statement does not exist` error. The pooled companion output (`db_url_with_pooler`) is never referenced anywhere in this repo's workflows.

**Vercel Authentication (SSO) protection is enabled on this project.** Every deployment except custom-domain ones requires a Vercel account with team access to view — including the preview URLs `deploy-preview.yml` posts as PR comments. An external reviewer without Vercel team access can't open those links without a bypass token. This also means any browser-automation test (e.g. Playwright) pointed at a live Vercel preview URL would hit Vercel's own auth wall before ever reaching the app or Clerk's sign-in — scope automated tests to a local dev server instead, unless a Protection Bypass token is wired in.

**`deploy-preview.yml`'s `vercel pull` must run before writing `VITE_API_URL`.** `vercel pull`/`vercel env pull` fully overwrites `.env.local`, not merges into it — so the per-PR backend URL has to be appended _after_ the pull, or it gets silently wiped out before `vercel build` runs.
