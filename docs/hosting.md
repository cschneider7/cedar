# Hosting & environments

Frontend and backend (Rust/Axum) both run as one Vercel project, same-origin; Postgres on Neon; auth via Clerk. Backend and frontend used to be split across Vercel and Fly.io — that split is gone as of the Vercel Functions migration (`.claude/specs/migrate-to-vercel-functions.md`). This doc is the durable record of how the pieces are wired together across dev/preview/prod.

- **Clerk**: single test-mode instance (`pk_test_`/`sk_test_` keys) — see "Shared Clerk instance" gotcha below.

## Environment matrix

|                | Dev (local)                                                                                               | Preview (per-PR)                                                                                                                   | Production                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| App            | `npm run dev` + `cargo run` (or docker-compose `frontend`/`backend` services), cross-origin `5173 → 3000` | One Vercel preview deployment (frontend + backend, same-origin), built automatically by Vercel's native Git integration on PR push | One Vercel production deployment, via Vercel's native Git integration (auto-deploy on push to `main`) |
| Database       | docker-compose Postgres container, or the Neon `dev` branch directly                                      | Neon branch provisioned by the Vercel-Neon Marketplace integration; `DATABASE_URL` auto-injected into that PR's Preview env        | Neon `production` branch; `DATABASE_URL` set manually as a Vercel Production env var                  |
| Clerk keys     | Local `.env` (`CLERK_SECRET_KEY`/`VITE_CLERK_PUBLISHABLE_KEY`)                                            | Vercel Preview-scoped env vars (same shared test-mode keys)                                                                        | Vercel Production-scoped env vars (same shared test-mode keys)                                        |
| Object storage | Local `.env` (`S3_*`, both halves) + docker-compose `minio`/`minio-init` services (MinIO)                 | Vercel Preview-scoped env vars (Cloudflare R2)                                                                                     | Vercel Production-scoped env vars (Cloudflare R2)                                                     |

Migrations run as part of the Vercel build itself: `vercel.json`'s `buildCommand` installs `sqlx-cli` and runs `sqlx migrate run` against `DATABASE_URL_UNPOOLED` (the Neon-integration-injected unpooled connection string for whichever branch that build belongs to) before `npm run build`. This applies to every environment — Preview on each PR push, and Production on merge to `main` — and gates the deploy: a failing migration fails the build outright.

## Gotchas

**Shared Clerk instance across all three environments.** There is deliberately no separate Clerk production instance yet — Clerk requires a custom domain you own to create one (for DNS-based session/email management), and this project doesn't have one. Decided 2026-08-04: stay on the shared `sk_test_`/`pk_test_` keys everywhere until a domain is purchased, then: buy domain → point at Vercel → create a Clerk production instance against it → rotate secrets, all before any real user signs up.

**Runtime DB connection: pooled `DATABASE_URL` + `statement_cache_capacity(0)`, not unpooled.** sqlx's client-side prepared-statement cache uses _named_ prepared statements by default, which can go missing when Neon's pooled/PgBouncer transaction-mode connection routes different statements from the same logical connection to different backend servers between transactions — surfacing as the same `prepared statement does not exist` error, but at request-serving time rather than build time. `AppState::build()` (`src/lib.rs`) sets `.statement_cache_capacity(0)` on `PgConnectOptions`, which makes sqlx use unnamed (unpinned) prepared statements instead — safe under transaction pooling. Verified during the spike: 40/40 test queries against the real pooled connection, zero failures. This lets the app use the pooled connection string everywhere (bounding Neon connection count as Fluid Compute spins up multiple concurrent instances, each with its own `MAX_CONNECTIONS`-sized pool) without needing the unpooled string at all.

**Vercel Authentication (SSO) protection is enabled on this project.** Every deployment except custom-domain ones requires a Vercel account with team access to view. This applies to the API too, not just the frontend, now that both are the same project — `vercel curl` (beta) auto-handles the deployment protection bypass for manual testing (`vercel curl <path>`); for Playwright/e2e or other scripted access, generate a **Protection Bypass for Automation** secret (Project Settings → Deployment Protection) and send it as the `x-vercel-protection-bypass` header.

**Object storage requires manual provisioning per environment.** Local dev's MinIO is self-contained (docker-compose), but Preview/Production need a real Cloudflare R2 bucket + API token (`S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY`) created out-of-band, then set as Preview/Production-scoped Vercel env vars (`S3_BUCKET`/`S3_REGION`/`S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY`/`S3_ENDPOINT`; `S3_REGION` is always `auto` for R2).

**`vercel.json`'s rewrite destination is the bare function path, not a path-preserving prefix.** `{ "source": "/api/v1/:path*", "destination": "/api/index" }` — Vercel forwards the original request (full path intact) to the function; the rewrite only decides _which_ function handles it. The Axum router inside `api/index.rs` (via `vercel_runtime`'s `VercelLayer`) still matches on the real incoming path, so routes are declared in `src/routes.rs` exactly as before (`/api/v1/students`, etc.) with no extra prefix stripping/rewriting needed on the Rust side. `/health` needs its own separate rewrite rule since it's outside `/api/v1`.
